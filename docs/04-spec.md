# Техническое задание

Источники: `docs/01-idea.md`, `docs/02-scheme.md`, `docs/02-scheme-graph.html`,
артбук №2 из `docs/03-artbooks.html`, `docs/03-prototype-notes.md`, папка `prototype/`.
Все подтверждены пользователем.

## Стек технологий

| Слой | Решение |
| --- | --- |
| Фреймворк | Next.js 16, App Router |
| Язык | TypeScript |
| Стили | Tailwind CSS 4 |
| Шрифты | `next/font/google`: Unbounded, Manrope, JetBrains Mono |
| Рендеринг | статическая генерация всех страниц |
| Хостинг | Vercel |
| Бэкенд | не нужен |
| База данных | не нужна |

Обоснование:

- Данных, которые меняются в рантайме, нет. Тарифы, состав работ и условия оплаты —
  константы в коде, значит все страницы генерируются статически и отдаются с CDN.
- Next.js выбран вместо чистой статики, потому что восемь тарифов описываются
  один раз в типизированном файле данных и раскладываются по карточкам, а не дублируются
  в разметке. Правка цены — одно число в одном месте.
- TypeScript ловит расхождения в данных на сборке: если у тарифа забыли срок или список
  пунктов, проект не соберётся.
- Tailwind 4 — та же связка, что в предыдущем проекте владельца, и токены артбука
  задаются один раз в `@theme`.
- Vercel: пуш в `main` разворачивает сайт, отдельная настройка сервера не нужна.

Что стек сознательно не включает: базу данных, аутентификацию, аналитику, CMS,
обработку форм. Ничего из этого в проекте нет.

## Страницы и компоненты

Маршруты берутся из `src/lib/routes.ts`, чтобы ссылки не расходились с папками.

### `/` — Главная в интерфейсе очков, с оверлеем входа

- **Компоненты:** `EntryOverlay`, `Glass`, `Topline`, `SectionHead`, `CategoryTile` ×2,
  `ChoiceHint`, `CategoryTile` ×2 (блок «Дальше»), `FootNav`.
- **Логика:**
  - Вход показывается оверлеем поверх готовой главной, а не отдельным маршрутом.
    Это даёт два эффекта: содержимое главной уже отрисовано под оверлеем, и возврат
    в раздел из меню не проигрывает вход заново.
  - Состояние оверлея: `start` → `play` → `boot` → снят.
    - `start`: постер `poster.webp` на весь экран, поверх кнопка «Войти» и подпись
      «подключение к креслу».
    - `play`: воспроизводится `scene.mp4`, в правом нижнем углу кнопка «Пропустить».
    - `boot`: затемнение, фраза «Всё ограничено вашей фантазией», полоса на 1,6 с.
    - снят: оверлей размонтируется, страница разблокирована.
  - Факт прохождения входа пишется в `sessionStorage` под ключом `entered`.
    При переходе по внутренним ссылкам и при возврате назад в течение сессии оверлей
    не показывается. Новая вкладка — вход снова.
  - Пока оверлей на экране, у `body` стоит блокировка прокрутки; при снятии снимается.
  - Видео: `muted`, `playsInline`, `preload="auto"`. Если `play()` отклонён браузером —
    сразу переход в состояние `boot`, застывший кадр показывать нельзя.
  - При `prefers-reduced-motion: reduce` ролик пропускается: кнопка «Войти» ведёт
    сразу в `boot` без анимации полосы.
- **Данные:** `site.ts` (посыл, описание, ссылка Telegram), `tiers.ts` (названия
  категорий, минимальная цена и вилка сроков по каждой).

### `/prostoy-sayt` — Тарифы: Простой сайт

- **Компоненты:** `Glass`, `Topline`, `SectionHead`, `TierList` → `TierCard` ×4,
  `ChoiceHint`, `FootNav`.
- **Логика:**
  - Карточка свёрнута по умолчанию. Раскрытие по клику на всю шапку карточки.
    Реализация на `<details>/<summary>`: работает без JavaScript и доступна с клавиатуры.
  - Открытыми могут быть несколько карточек одновременно — это решение пользователя.
  - В свёрнутом виде: `TierMock` (макет-превью), название, срок, короткая суть,
    старая цена зачёркнутой и новая рядом, подпись «подробнее».
  - В раскрытом: полный список того, что входит, и ссылка на раздел «Что входит».
  - Кнопки Telegram внутри карточек нет — единственная в шапке.
- **Данные:** `tiers.ts`, категория `simple`.

### `/sredniy-funktsional` — Тарифы: Средний функционал

Полностью повторяет предыдущую страницу, отличается набором данных
(категория `middle`) и текстом подсказки выбора.

### `/chto-vhodit` — Что входит «под ключ»

- **Компоненты:** `Glass`, `Topline`, `SectionHead`, список из десяти пунктов,
  `CategoryTile` ×2, `FootNav`.
- **Логика:** статика, интерактива нет.
- **Данные:** `included.ts`, минимальные цены из `tiers.ts` для плиток внизу.

### `/usloviya` — Условия работы

- **Компоненты:** `Glass`, `Topline`, `SectionHead`, блок правил правок,
  четыре карточки этапов оплаты, `CategoryTile` ×2, `FootNav`.
- **Логика:** статика.
- **Данные:** `terms.ts`.

### `not-found.tsx` — 404 «Сигнал потерян»

- **Компоненты:** `Glass`, `Topline`, крупный код ошибки, две кнопки возврата,
  `CategoryTile` ×2, `FootNav`.
- **Логика:** отдаётся Next.js на любой несуществующий путь. Оверлей входа
  не показывается.

### `error.tsx` — Аварийный экран

- Ловит непредвиденные ошибки рендера, показывает то же оформление, что и 404,
  с кнопкой «Повторить». Технические детали ошибки пользователю не выводятся.

## Модель данных

Данные статичные, лежат в TypeScript-файлах и проверяются компилятором.
База данных не используется.

### Category — категория тарифов

- Поля и типы:
  - `id: "simple" | "middle"`
  - `title: string`
  - `note: string` — пояснение к категории
  - `termRange: string` — вилка сроков по категории, например «3–12 дней»
  - `hint: { stay: string; leave: string }` — тексты подсказки выбора
- Связи: одна категория содержит четыре `Tier`.

### Tier — тариф

- Поля и типы:
  - `id: string` — латиницей, уникален в пределах сайта
  - `categoryId: Category["id"]`
  - `title: string`
  - `term: string` — срок исполнения
  - `gist: string` — суть пакета одной строкой для свёрнутой карточки
  - `basePrice: number` — цена по прайсу в рублях, целое число
  - `includes: string[]` — состав пакета
  - `mock: MockLayout` — описание макета-превью
  - `order: number`
- Связи: принадлежит одной `Category`.
- Правило цены: цена со скидкой считается в `lib/price.ts` как
  `basePrice * (1 - promo.percent / 100)`, округление не применяется —
  32 000 × 0,6 даёт ровно 19 200. Значения со скидкой в данных не хранятся,
  чтобы прайс и витрина не разъехались.

### MockLayout — макет-превью пакета

- Поля и типы:
  - `rows: MockRow[]`, где `MockRow` — один из вариантов:
    `{ kind: "bar"; accent?: "yellow" | "teal"; tall?: boolean }`,
    `{ kind: "grid"; cols: 2 | 3; filled?: boolean }`,
    `{ kind: "side" }` — колонка меню плюс сетка карточек
- Назначение: превью рисуется из данных, а не из разметки, поэтому все восемь
  превью гарантированно одного визуального языка.

### IncludedItem — пункт состава «под ключ»

- Поля и типы: `text: string`, `note?: string`, `order: number`.

### PaymentStage — этап оплаты

- Поля и типы: `percent: number`, `title: string`, `condition: string`, `order: number`.
- Правило: сумма `percent` по всем этапам обязана равняться 100. Проверка выполняется
  на сборке; при несовпадении сборка падает с понятной ошибкой.
- Текущие значения: 10 / 30 / 30 / 30.

### RevisionPolicy — правила правок

- Поля и типы: `rule: string`, `exceptions: string[]`.

### Promo — акция

- Поля и типы: `percent: number` (сейчас 40), `condition: string`, `until?: string`.
- Связи: применяется ко всем `Tier` без исключения.

### Contact — канал связи

- Поля и типы: `kind: "telegram"`, `href: string`, `label: string`.
- Сейчас канал один. Тип оставлен расширяемым на случай добавления почты.

### SceneAsset — материалы входа

- Поля и типы: `video: string`, `poster: string`, `lastFrame: string`,
  `durationSec: number`.
- Пути ведут в `public/scene/`. Подмена ролика — замена файла, код не меняется.

## API и эндпоинты

Не требуются. Форм на сайте нет, данные пользователя не принимаются и не хранятся,
всё содержимое известно на этапе сборки. Серверных маршрутов в проекте быть не должно.

Если позже появится форма заявки (в `docs/02-scheme.md` она значится в разделе
«Потом»), добавляется один маршрут `POST /api/lead` с отправкой в Telegram Bot API.
Сейчас он не реализуется.

## Интеграции

- **Telegram** — единственная. Обычная ссылка вида `https://t.me/<username>` в шапке
  каждой страницы. Ни SDK, ни виджета, ни бота.
- Аналитика **не подключается**: пользователь решил, что сбора данных на сайте нет.
- Сторонние скрипты, чаты, пиксели и шрифтовые CDN не используются: шрифты
  подгружаются через `next/font` и раздаются со своего домена.

## Безопасность и надёжность

Мер меньше обычного, потому что сайт не принимает ввод, не хранит данные и не имеет
учётных записей. Обязательны к исполнению:

- **HTTPS** на всём трафике: обеспечивается Vercel, HTTP редиректится на HTTPS.
- **Заголовки безопасности** в `next.config.ts`:
  `Content-Security-Policy` с `default-src 'self'` и явным разрешением только на то,
  что действительно используется; `X-Content-Type-Options: nosniff`;
  `Referrer-Policy: strict-origin-when-cross-origin`; `X-Frame-Options: DENY`,
  чтобы сайт нельзя было встроить в чужую страницу и выдать за своё предложение.
- **Внешние ссылки** (Telegram) — с `rel="noopener noreferrer"`, чтобы открытая
  вкладка не получала доступ к странице-источнику.
- **Никакого пользовательского ввода** — форм, поиска и параметров запроса,
  влияющих на разметку, нет. Следовательно, нет и поверхности для XSS-инъекции
  через ввод. Если форма появится позже, к ней добавляются валидация на сервере,
  ограничение частоты запросов и защита от ботов.
- **Секреты** не хранятся в репозитории. Сейчас их нет вовсе; при появлении
  Telegram-бота токен уходит в переменные окружения Vercel и не коммитится.
- **Обработка ошибок**: `not-found.tsx` и `error.tsx` показывают оформленный экран
  без стеков вызовов, путей на диске и прочих внутренних деталей.
- **Отказ видео не ломает вход**: если браузер не дал воспроизвести ролик, отклонил
  автозапуск или файл не загрузился, оверлей переходит к экрану загрузки и пускает
  человека на сайт. Никакой ветки, где посетитель упирается в застывший кадр.
- **Доступность как часть надёжности**: раскрытие карточек на `<details>` работает
  без JavaScript, кнопки — настоящие `<button>` с видимым состоянием фокуса,
  у видео `aria-hidden` и текстовая альтернатива происходящего, контраст текста
  к фону не ниже 4,5:1.
- **Уважение к системным настройкам**: при `prefers-reduced-motion: reduce`
  ролик и анимации не проигрываются.
- **Бюджет загрузки**: первый экран не должен тянуть больше 400 КБ без учёта ролика;
  ролик грузится параллельно и не блокирует отрисовку кнопки «Войти».

## Принятые рекомендации

Все четыре приняты пользователем 7 сентября 2026 и входят в объём работ.

- **Скидка в переменной окружения.** Размер акции читается из `NEXT_PUBLIC_PROMO_PERCENT`
  со значением по умолчанию 40. Акцию можно отключить (`0`) или изменить процент
  без правки данных и без пересборки локально — достаточно поменять переменную
  в Vercel и перевыпустить сборку. При нуле зачёркнутая цена не показывается,
  выводится только прайсовая.
- **Проверка данных через Zod.** На `tiers.ts`, `included.ts` и `terms.ts` пишутся схемы
  и прогоняются при импорте данных. Схемы ловят: пропущенное поле, отрицательную
  или нулевую цену, пустой список того, что входит, сумму процентов по этапам
  оплаты не равную 100, дублирующиеся идентификаторы тарифов. Ошибка схемы валит
  сборку с текстом, называющим конкретный тариф и поле.
- **Ролик в двух форматах.** В `public/scene/` кладутся `scene.webm` (VP9) и `scene.mp4`
  (H.264). В разметке два `<source>`, WebM первым: браузер берёт поддерживаемый,
  Safari остаётся на mp4. Обе дорожки без звука.
- **Только пути из `routes.ts`.** Внутренние ссылки берутся из `ROUTES`, строковые
  литералы в `href` запрещены правилом ESLint (`no-restricted-syntax` на строковый
  `href`, начинающийся со `/`). Переименование раздела правится в одном месте
  и ломает сборку везде, где ссылка не обновлена.
